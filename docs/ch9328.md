# CH9328 keyboard bridge

The Adafruit CH9328 + USB-to-TTL adapter sends KVM hotkeys and ordinary keyboard
shortcuts while the Pi keeps its USB-C power supply and IR HAT. The standalone
digit and KVM tests passed on the user's hardware. Verify the integrated
numpad-to-KVM flow after deployment.

## Update and switch the existing Pi

On the development computer:

```bash
cd /home/you/Documents/Code/desk-orchestrator
bash deploy/update-pi.sh pi@192.168.1.50
```

The updater installs `pyserial` through the `serial` extra, adds `desk` to
`dialout`, and removes the controller service's hard dependency on
`desk-gadget.service`. It preserves other service settings and saved configuration.
The previous controller unit is included in rollback. Serial group membership,
like installed system dependencies, remains after rollback.

On the Pi, with the bridge connected and the standalone test script closed:

```bash
sudo /opt/desk-orchestrator/.venv/bin/python -m desk_orchestrator.configure_keyboard
```

The command selects an adapter only when exactly one USB serial adapter has a
stable alias. It prefers `/dev/serial/by-id/`, then `/dev/serial/by-path/`.
For multiple adapters or no stable alias, it stops before changing anything;
identify the tested adapter and supply its path explicitly:

```bash
ls -l /dev/serial/by-id/ /dev/serial/by-path/
sudo /opt/desk-orchestrator/.venv/bin/python -m desk_orchestrator.configure_keyboard \
  --device /dev/serial/by-id/YOUR_ADAPTER
```

It checks service-account access without opening the UART, backs up the settings
to a dated `controller.before-ch9328-*.json` beside `controller.json`, saves the
transport at 9600 baud with the existing key timing, marks the already-tested
wiring verified, disables/stops the old gadget service, and restarts previously
active app/listener services. It sends no keys and does not enable an inactive
listener. Tasks, numpad mappings, IR codes, credentials, and media bindings remain.

Keep adapters without unique serial numbers in the same USB port when using
`by-path`. A permanent `/dev/ttyUSB0` path can change when devices reconnect.

## Edit in the app

Open **Hardware → Level1Techs KVM → Control settings**. Keep **USB keyboard / KVM**
as the control method and choose **CH9328 USB-to-serial bridge** for **Keyboard
connection**. Select the discovered serial path, use a key delay of 0.08 seconds,
and save. Suggestions describe the host running the web app; use the Pi's app
to discover its adapter. Missing devices can be entered manually. Page loading
and saving never send keys or open a port.

The commissioning command above also performs this configuration and disables
the gadget service. If configuring entirely through the UI after updating, run
`sudo systemctl disable --now desk-gadget.service` on the Pi afterward.

## Wiring and protocol

The serial adapter connects to a Pi USB-A port; the CH9328's USB-C data cable
goes to the KVM keyboard/HID port. With USB disconnected, connect adapter green
TX to CH9328 JST white RX, and black ground to black ground. Leave adapter white
RX and both red power leads disconnected and insulate unused leads individually.
CH9328 is powered by its USB-C connection.

Set switches **1 ON, 2 OFF, 3 ON, 4 ON** before powering the CH9328; power-cycle
after changing switches. Output is **9600 baud, 8N1, no flow control**, using
eight-byte Mode 3 reports. No CircuitPython, Blinka, GPIO, or SWIG dependency is
needed. Sources: [wiring](https://learn.adafruit.com/adafruit-ch9328-uart-to-hid-keyboard-breakout/cpython),
[Mode 3](https://learn.adafruit.com/adafruit-ch9328-uart-to-hid-keyboard-breakout/circuitpython-and-python),
[report format](https://github.com/adafruit/Adafruit_CircuitPython_CH9328/blob/main/adafruit_ch9328/ch9328.py),
[pyserial settings](https://pyserial.readthedocs.io/en/latest/pyserial_api.html).

## Commands and limitations

Existing KVM actions automatically use the selected output. Port switching sends
left Ctrl, release, left Ctrl, release, top-row 1–4, release. Keyboard bindings
and macros use the existing shortcut generator. Each macro holds one exclusive
serial session and the shared scene lock. Every press is released; failures
attempt a final release and stop without replay. A later request reopens the
adapter, allowing recovery after reconnection.

In a task's **Keyboard mapping** editor, select a numpad key and choose
**Keyboard sequence**. Enter a shortcut such as `Win+R` (`Super+R` and `Meta+R`
are equivalent), `Cmd+Space`, or `Ctrl+Alt+T`. Add more shortcut steps and delays
as needed. Save and activate the task, then press its assigned physical or
virtual numpad key. Each task can define a different sequence for the same key.
Commands go to the computer currently selected on the KVM, using its keyboard
layout and configured shortcuts. Extended keys depend on bridge firmware and
host support. No new hardware or serial configuration is needed.

Existing keyboard presets are shown as editable shortcuts. Saved legacy media
commands remain visible until explicitly replaced or cleared; the editor no
longer offers new media presets. To control media using this bridge, enter the
ordinary keyboard shortcut configured in the receiving operating system or app.
Whether it works while another app is focused depends on that computer's shortcut
configuration.

The CH9328 Mode 3 UART format accepts eight-byte Keyboard reports, not USB HID
Consumer Control reports. Legacy media presets retain their original Consumer
Control meaning, and a sequence containing one is rejected in full before the
serial port is opened. They are not automatically translated to app shortcuts.
The Pi USB gadget transport still supports legacy media commands through its
separate Consumer Control interface. The old `media_shortcuts` data is retained
in task edits and backups but remains unused.

Sources: [CH9328 datasheet, page 4](https://cdn-learn.adafruit.com/assets/assets/000/130/514/original/CH9328DS1.PDF),
[Adafruit Consumer Control codes](https://docs.circuitpython.org/projects/hid/en/latest/api.html#adafruit-hid-consumer-control-code-consumercontrolcode).

Diagnostics identify `ch9328`, the serial path, and transmitted reports.
A successful write means **command sent**, not confirmation of the selected KVM
port. Connection checks inspect device access without sending keys.

After deployment, use a KVM-only test task first, then check ports 1, 2, and 3
through the physical and virtual numpads. Test a keyboard binding in a blank
editor, then reconnect the adapter and repeat. Errors appear in **Settings →
Developer Console**. If a key remains held after a disconnected UART, unplug
and reconnect the CH9328 USB cable to reset the keyboard.

## New installations and recovery

```bash
sudo bash deploy/setup-pi.sh --keyboard-transport ch9328 --reboot
```

This installs IR and the app without requiring the Pi USB gadget, `/dev/hidg0`,
or a `dwc2` overlay. Then run the commissioning command to select the actual
adapter and save the transport. Later setup runs use the saved transport by
default. CH9328 setup removes `dwc2` only from the installer's managed boot
block; external USB settings are preserved.

To return to the Pi USB gadget, choose that connection in Hardware, restore
its keyboard/media paths, and rerun setup with `--keyboard-transport gadget
--reboot` after restoring the appropriate physical power/data wiring. Before
rolling back code to a version predating CH9328, restore gadget settings; older
versions cannot use serial output. The dated configuration backup is owned by
`desk` with private permissions.

## Verification

Install `.[web,keypad,tls,serial]` for all tests. Tests cover a real pyserial
pseudo-terminal, all port digits, macro timing, release after failures and
interruptions, unsupported Consumer Control rejection before transmission, read-only probes,
shared locking, stable path selection, configuration backup/preservation, editor
save/reload, serial permissions, gadget-independent setup, and unit rollback.
